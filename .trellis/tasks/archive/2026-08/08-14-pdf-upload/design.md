# 支持上传文档文件：技术设计

## 边界与兼容性

- 保持 `POST /api/images`、multipart 字段 `image` 和 `GET /images/{name}` 不变，避免影响现有页面、自动化和已发布链接。
- 将后端以 `imageType` 为中心的实现收敛为通用上传类型表。每种类型定义 MIME、存储扩展名、大小上限、校验策略和公开响应策略。
- 已保存图片继续使用原文件名与公开 URL；新增文档仍写入相同上传目录，但文件名扩展名由服务端确认的类型决定。

## 上传与验证

1. 浏览器使用允许类型表校验拖放或选择的文件，并按类型显示 10 MiB 图片上限或 50 MiB 文档上限。
2. 请求仍使用 `/api/images` 与字段 `image`。服务端先限制整个 multipart 请求，再限制单文件读取；文档与图片都不信任客户端文件名。
3. 服务端解析声明 MIME，查找允许类型，并基于读取到的内容确认类型；声明类型与确认类型不一致则返回 `415`，空文件返回 `400`，超过对应类型上限返回 `413`。
4. 图片继续使用 HTTP 内容检测。PDF 验证 `%PDF-` 文件头；TXT 和 MD 验证有效 UTF-8（允许 BOM）；EPUB 和 OpenXML 格式解析 ZIP 中央目录，检查各格式必需的成员与标识。
5. ZIP 验证只读取受大小限制的必需元数据，拒绝异常条目计数、目录名或声明解压大小，避免为识别文件而解压不受控内容。
6. 持久化沿用随机 16 字节十六进制名称、排他创建、`0640` 权限和失败清理。

## 公开访问

- 文件名正则扩展为所有允许的服务端扩展名，继续拒绝任意路径和客户端文件名。
- 通过扩展名确定 MIME，不进行嗅探，并保留 `X-Content-Type-Options: nosniff` 与长期缓存策略。
- PDF、TXT、MD 使用 `Content-Disposition: inline`；EPUB、DOCX、XLSX、PPTX 使用 `Content-Disposition: attachment`。下载文件名为服务器生成的随机文件名，避免将未经处理的原始文件名放入响应头。

## 前端交互

- 上传区标题、支持格式说明、文件选择器 `accept` 和错误文案扩展为图片与文档。
- 图片维持对象 URL 图片预览和完成预览。
- 文档选择与完成状态改用文档类型标签/图标、文件名、大小和链接，不给 `img` 设置文档 URL。
- 保留进度、复制、重选、继续上传和登录过期跳转的现有交互。

## 风险与回滚

- 50 MiB 文件会增加单次请求内存占用；当前架构已在内存中读取文件，首版保持这一行为并以严格上限约束。生产环境需监控磁盘使用量。
- 压缩容器可能伪装或膨胀，校验仅接受格式特征明确的 EPUB/OpenXML 包并限制元数据读取。
- 回滚只需部署前一版本；已存的新增文件会因旧版本的路径白名单返回 404，但不会影响既有图片。

## ECS2 部署

- 目标通过 SSH 别名 `ecs2` 访问，现有服务二进制路径为 `/opt/image-host/current/image-host`，上传目录为 `/var/lib/image-host/uploads`。
- 在本地完成测试后构建静态 Linux amd64 二进制，上传至新的 `/opt/image-host/releases/<release>/` 目录；验证文件存在后原子更新 `current` 软链接并重启 `image-host.service`。
- ECS2 的 `/usr/local/nginx/conf/conf.d/image.zhangjianyong.top.conf` 当前请求体上限为 `11m`，需备份后调整为 `51m`。执行 `/usr/local/nginx/sbin/nginx -t` 成功后才重载 Nginx。
- 发布后通过 HTTPS 验证登录、50 MiB 以下文档上传、公开文件访问和既有图片访问。若任一步失败，切回前一 `current` 软链接并重启服务；若 Nginx 检查失败，恢复备份且不重载。
